## 1. Contexto

O documento de Engenharia de Software definiu o RNF03 como “Armazenamento local dos dados (privacidade)”. A arquitetura do FinApp utiliza Kotlin, Spring Boot e Spring Data JPA e já contempla PostgreSQL executado localmente por Docker na Demo v1, conforme informado pela equipe.

O repositório contém um perfil de desenvolvimento com H2 em memória e um perfil Docker com PostgreSQL. O registro explicita o que significa armazenamento local na execução adotada para a aplicação, alinhando o requisito com as escolhas técnicas existentes.

## 2. Decisão

Utilizar PostgreSQL em contêiner Docker executado localmente, com a aplicação conectada ao banco pelo perfil Docker. O H2 permanece disponível no perfil de desenvolvimento local; ele não substitui o PostgreSQL no ambiente Docker.

Adotar a seguinte redação do RNF03 na seção 2 do Plano de Projeto:

> Os dados devem ser armazenados em banco de dados executado localmente (Docker), sem envio a serviços externos.

Essa restrição se refere aos dados financeiros armazenados pela aplicação. Sua observância deve ser verificada na configuração e na execução do sistema.

## 3. Justificativa

- Alinhar o RNF03 à arquitetura Kotlin/Spring Boot/JPA e à execução com PostgreSQL já presente no projeto.
- Documentar a execução reproduzível do banco e da aplicação por Docker Compose para a equipe e para a demonstração.
- Preservar o armazenamento dos dados financeiros no ambiente local de quem executa a aplicação.
- Manter os limites atuais do produto, que excluem autenticação, entidade Usuario e funcionalidades multiusuário.

A execução local é uma restrição de armazenamento; ela não representa, por si só, comprovação de segurança ou aprovação formal deste registro.

## 4. Alternativas consideradas

O material fornecido não informa quais alternativas foram efetivamente discutidas pela equipe na data da decisão. Para apoiar a validação deste registro, a comparação documental é:

| Alternativa | Análise | Situação |
|---|---|---|
| H2 em memória | Simplifica o desenvolvimento local, mas os dados desse perfil não permanecem após o encerramento da aplicação. | Mantido no perfil de desenvolvimento; não adotado como banco do ambiente Docker. |
| PostgreSQL instalado diretamente na máquina | Permite armazenamento local, mas exige instalação e configuração próprias em cada máquina. | Alternativa de comparação; discussão pela equipe a confirmar. |
| PostgreSQL em Docker local | Mantém o banco local e permite descrever sua execução no Docker Compose existente. | Escolha técnica adotada no projeto; formalização pendente. |

A equipe deverá confirmar o histórico das alternativas antes de apresentar esta seção como relato de uma reunião ou deliberação.
